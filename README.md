## Локальная разработка и база данных

Скопируйте `.env.example` в `.env` и задайте свой `DJANGO_SECRET_KEY`.
Локальный `.env` не попадает в Git и Docker-образ. Для `make run` и `make dev`
используйте `DJANGO_DEBUG=True`: Django покажет подробные ошибки и будет
автоматически отдавать файлы статики при разработке.

При запуске через `make run` Django использует `db.sqlite3` в корне проекта.
Значение `DATABASE_URL` из `.env` при локальном запуске игнорируется, поэтому
локальная база сохраняется между перезапусками. После первого запуска или
обновления проекта выполните `make migrate`.

В Docker переменная `DJANGO_IN_DOCKER=1` задаётся в Dockerfile. В этом режиме
Django подключается по `DATABASE_URL`, а `entrypoint.sh` применяет миграции
при запуске контейнера. База должна храниться вне временной файловой системы
контейнера, если её данные нужны после пересоздания контейнера.

На сервере задайте `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`
и `DATABASE_URL` как переменные окружения контейнера. Локальный `.env` перед
деплоем менять не нужно. Если итоговая настройка Django всё же даст `DEBUG=True`,
`entrypoint.sh` завершится с ошибкой до миграций и запуска Gunicorn.

Перед деплоем запускайте `python manage.py check --deploy` с **серверными**
переменными окружения. Команда проверяет настройки безопасности Django и
выводит предупреждения, например о HTTPS и защищённых cookie. Обычный
`manage.py check` не включает эти дополнительные проверки. Проверка не
исправляет настройки и без `--fail-level WARNING` может завершиться успешно
даже при предупреждениях. Для автоматического блокирования деплоя по ним
используйте `python manage.py check --deploy --fail-level WARNING`, когда
настроите все нужные параметры безопасности.

## Файлы публикаций

В админке на странице публикации добавьте вложения в разделе «Файлы публикации».
У опубликованной статьи ссылки скачивания видны сотрудникам (право
`education.view_internal_materials`, группа «Сотрудники») и администраторам.
Остальные посетители не могут скачать файлы даже по прямой ссылке.

Файлы хранятся отдельно от публичного `media`: по умолчанию в
`private_publications/`, путь можно задать через `PRIVATE_PUBLICATIONS_ROOT`.
На сервере разместите этот каталог на постоянном томе и включите его в резервное
копирование. Не настраивайте для него прямую раздачу через nginx или другой
веб-сервер: скачивание должно проходить через Django с проверкой прав.
После обновления выполните `make migrate`.

## Курсы лекций

В админке раздела `education` создайте курс, затем лекции. На странице курса
можно добавить лекции и перейти к их редактированию; на странице лекции —
заполнить примечание и загрузить презентации и дополнительные файлы.
Для отображения включите «Показывать на сайте» и у курса, и у лекций.

Внизу страницы «Учебные материалы» сотрудники с правом
`education.view_internal_materials` и администраторы видят список курсов.
На странице курса лекции раскрываются вместе с примечаниями и вложениями.
PDF можно открыть в браузере, все вложения — скачать. Страницы курсов,
просмотр и скачивание файлов проверяют права и публикацию материала.
Файлы хранятся в `PRIVATE_PUBLICATIONS_ROOT/education/lectures/`, вне публичного
`media`. Изменение вложения само по себе не обновляет дату записи лекции;
для её обновления сохраните лекцию в админке.

## Диссертации

В админке раздела «Наука» добавьте диссертацию: название, внешнюю ссылку,
автора, год защиты, вид диссертации, специальность и руководителей.
Включите «Показывать на сайте», чтобы карточка появилась на странице «Наука».
Отдельных страниц диссертаций нет: название ведёт на внешний источник.

Необязательный текст диссертации хранится в `PRIVATE_PUBLICATIONS_ROOT`
в подкаталоге `dissertations/<год защиты>/`. Скачивание доступно сотрудникам с правом
`education.view_internal_materials` и администраторам; прямой доступ через
публичный `media` отсутствует. После обновления выполните `make migrate`.

## Выпускные квалификационные работы

Модель `research.Diploma` редактируется в админке в разделе «Выпускные
квалификационные работы». Автор выбирается из карточек людей; удалить карточку
автора, пока на неё ссылается ВКР, нельзя. Руководителей можно выбрать из
карточек, а внешних — указать текстом. Уровни: бакалавриат, магистратура,
специалитет. Название и внешняя ссылка обязательны, текст работы необязателен.

Файлы хранятся в `PRIVATE_PUBLICATIONS_ROOT/diplomas/<год защиты>/`.
Скачивание опубликованных работ доступно сотрудникам и администраторам.
Изменение года защиты не перемещает ранее загруженный файл.
Опубликованные ВКР отображаются на странице «Наука» под защищёнными
диссертациями. Название ведёт на внешний ресурс, автор и руководители —
на их карточки, если они опубликованы.
После обновления выполните `make migrate`.

## Парсеры библиографических файлов

`publications/importers.py` разбирает ровно одну публикацию из BibTeX или RIS.
В админке на странице добавления публикации доступен блок «Заполнить из файла».
Выберите `.bib` или `.ris` и нажмите «Прочитать файл»: поля заполнятся без
сохранения. Проверьте предупреждения, выберите сотрудников и направления,
затем прикрепите вложения и сохраните карточку. При повторном импорте
браузер запрашивает подтверждение замены введённых данных; выбранные вложения
нужно добавить заново. Ошибка чтения сохраняет значения основной формы.

При найденном дубле показываются ссылки на существующие карточки. Для
сохранения отдельной записи нужно явно отметить подтверждение; проверка
повторяется при сохранении, включая редактирование (текущая карточка исключается).

Сам парсер не сохраняет записи,
не загружает вложения и не обращается к внешним API.

```python
from publications.importers import parse_publication, find_duplicates

result = parse_publication(uploaded_file)  # Django UploadedFile, UTF-8, до 2 МБ
# Либо parse_publication(text_or_bytes, format='bibtex') / format='ris'.
initial = result.data             # Значения полей Publication для формы
errors = result.errors           # Ошибки полей, которые нужно исправить
warnings = result.warnings       # Неизвестный тип и неперенесённые поля
unmapped = result.unmapped_fields  # Неперенесённые поля с исходными значениями
matches = find_duplicates(result)  # DuplicateMatch(publication, reason)
```

Пустой, повреждённый файл или несколько записей вызывают
`PublicationImportError`. Недостающие обязательные значения остаются в
`result.errors`: форму можно заполнить вручную. Неизвестный тип заменяется
на «Другое» с предупреждением. Публикация всегда предлагается как черновик.

Поиск дублей сравнивает нормализованный DOI, а при отсутствии DOI во входных
данных — название без различий регистра, пробелов и пунктуации вместе с годом.
Он включает неопубликованные карточки. Для редактирования можно передать
`exclude_pk`, для ограничения области поиска — `queryset`. Это кандидаты для
проверки человеком; записи не изменяются. При подключении к админке проверку
следует выполнять и перед сохранением.

Тесты: `uv run python manage.py test publications`.

## Учёные степени, звания и статус сотрудников

В админке карточки сотрудника доступны отдельные поля «Учёная степень»
(кандидат или доктор наук с указанием отрасли), «Учёное звание» (доцент или профессор) и
«Действующий сотрудник». Степень и звание необязательны и показываются
в списке сотрудников и личной карточке, если заполнены. Эти поля редактируются
через админку, а не через форму самостоятельного редактирования карточки.

После обновления выполните `make migrate`. Для существующих карточек степень
и звание остаются пустыми; все сотрудники по умолчанию считаются действующими.
Проверьте этот статус у бывших сотрудников. Он независим от публикации карточки
и активности аккаунта; пока статус не меняет состав публичного списка.
Для будущей статистики действующий состав выбирается через
`Employee.objects.current()`, только опубликованный — через
`Employee.objects.current().published()`. На странице истории статистика рассчитывается по всем действующим сотрудникам,
включая неопубликованные карточки. Научные сотрудники определяются по научной
должности; кандидаты и доктора наук считаются только среди них.

Степени и звания отображаются сокращённо: к.х.н., к.ф.-м.н., к.б.н.,
д.х.н., д.ф.-м.н., проф., доц. Ранее сохранённые степени без отрасли остаются
как «к.н. (отрасль не указана)» и «д.н. (отрасль не указана)» — уточните их
в админке. Для подсчёта по уровню степени используйте фильтр
`academic_degree__in=AcademicDegree.candidates()` или
`academic_degree__in=AcademicDegree.doctors()` из `users.models`.


## Студенты и аспиранты лаборатории

Все участники хранятся в `users.Employee` (в админке — «Карточки участников
лаборатории»). Статус обучения `education_status` необязателен: пустое значение,
«Студент» или «Аспирант». Он независим от научной и инженерной должности.
Поле `study_year` — необязательный положительный номер курса только для студентов;
курс обновляется вручную. При смене статуса на аспиранта или пустое значение
нужно очистить курс. Статус обучения и курс редактирует администратор; владелец
карточки по-прежнему меняет только ФИО, фото и описание.

На странице «Сотрудники» опубликованные карточки разбиты на сотрудников,
аспирантов и студентов. При наличии любой должности человек показан один раз
в разделе сотрудников с дополнительной подписью об обучении. Без должности
и с пустым статусом человек также остаётся в разделе сотрудников. Пустые разделы
скрыты. В разделах обучающихся используется алфавитная сортировка.
Все опубликованные карточки с выключенным признаком «Действующий участник»
показываются только в последнем разделе «Сотрудники и студенты лаборатории
в прошлом», по алфавиту, независимо от должностей и статуса обучения.
Статистика истории учитывает действующих участников без статуса обучения
и обучающихся с должностью, включая неопубликованные карточки.

Аккаунт необязателен. Для доступа студента или аспиранта к внутренним материалам
создайте аккаунт с ролью «Сотрудник»; при необходимости привяжите его к карточке.
Публикация карточки, статус обучения и признак действующего участника сами
по себе не дают и не отзывают доступ. Для его отзыва можно отключить аккаунт.
Роль «Сотрудник» даёт доступ к внутренним материалам, но не вход в админку.
Миграция `0006` снимает `is_staff` у существующих пользователей группы
«Сотрудники», кроме суперпользователей. Обратная миграция автоматически
не восстанавливает этот флаг. Роль «Администратор» сохраняет полный доступ.

После обновления выполните `python manage.py migrate`.
